## 需求需要创建一个用于构建一个符合TIS 插件规范的用户创建TIS插件的Claude Code Skill技能， Skill名称为`create-multi-steps-plugin`，由于在创建插件过程中插件属性之间存在逻辑依赖性，如：有一个UserRegisterPlugin的插件，内部有两个属性，如下：```javapublic class UserRegisterPlugin implements Describle<UserRegisterPlugin> {    @FormField(type = FormFieldType.ENUM, ordinal = 0, validate = {Validator.require})    public Integer province;        @FormField(type = FormFieldType.ENUM, ordinal = 1, validate = {Validator.require})    public Integer city;}```以上province,city属性在前端显示都是以下啦框的显示方式，city的下啦列表的显示是需要依赖于province的选择的，只有在选中某个province之后city下啦列表才显示某province下对应的city可选列表## 何时使用该skill用户明确说明需要调用该skill，或者或者辅助编程过程中发现某几个属性直接明显存在如上UserRegisterPlugin 插件的中的 province和city之间的语义依赖的情况（这种情况也需要经过用户确认）## TIS的插件规范是什么规范使用之前创建的一个`多步配置插件`的例子来说，例如：/Users/mozhenghua/j2ee_solution/project/plugins/tis-ontology-plugin/src/main/java/com/qlangtech/tis/plugin/ontology/impl/valuetype/DefaultOntologyValueType.java用于创建Ontology ObjectType实例的插件。`多步配置插件` 必须要有以下规范：1. 必须要实现`/Users/mozhenghua/j2ee_solution/project/tis-solr/tis-plugin/src/main/java/com/qlangtech/tis/extension/MultiStepsSupportHost.java`接口    插件类或者父类必须直接或者间接实现`MultiStepsSupportHost`接口   例如：DefaultOntologyValueType类继承于/Users/mozhenghua/j2ee_solution/project/tis-solr/tis-plugin/src/main/java/com/qlangtech/tis/plugin/ontology/OntologyValueType.java，OntologyValueType类实现了MultiStepsSupportHost接口2. 插件类必须拥有`protected OneStepOfMultiSteps[] stepsPlugin`的成员属性   插件类或者父类必须拥有stepsPlugin属性，并且需要实现`MultiStepsSupportHost`接口的两个虚方法：`setSteps`、`getMultiStepsSavedItems`，如下：   ```java         @Override    public void setSteps(OneStepOfMultiSteps[] stepsPlugin) {        this.stepsPlugin = Objects.requireNonNull(stepsPlugin, "stepsPlugin can not be null");        // FIXED_VALUE_TYPE_STEPS_LENGTH 代表该多步插件拥有的步骤数目        final int FIXED_VALUE_TYPE_STEPS_LENGTH = 2;        if (stepsPlugin.length != FIXED_VALUE_TYPE_STEPS_LENGTH) {            throw new IllegalStateException("stepsPlugin.length must be equal to" + FIXED_VALUE_TYPE_STEPS_LENGTH);        }    }    // 注意：必须要添加以下@JSONField(serialize = false) 标注，保证在json序列化插件的过程中不对getMultiStepsSavedItems() 返回的内容进行序列化    @JSONField(serialize = false)    @Override    public OneStepOfMultiSteps[] getMultiStepsSavedItems() {        return stepsPlugin;    }   ```3. 必须要实现`/Users/mozhenghua/j2ee_solution/project/tis-solr/tis-plugin/src/main/java/com/qlangtech/tis/plugin/IPluginStore.java:L171 ManipuldateProcessor`   插件类或者父类必须直接或者间接实现`MultiStepsSupportHost`接口,`manipuldateProcess()` 方法中实现将多步骤插件实现持久化功能，如：tis-plugin/src/main/java/com/qlangtech/tis/plugin/ontology/OntologyValueType.java:L152 所示4. 内部被 @TISExtension 标识的Descriptor类必须实现 `tis-plugin/src/main/java/com/qlangtech/tis/extension/MultiStepsSupportHostDescriptor.java`接口，   必须要实现`getHostClass()`、`getStepDescriptionList()`方法，如下`DefaultOntologyValueType.java:L112-L125`类中所示：   ```java        @Override        public Class<OntologyValueType> getHostClass() {            return OntologyValueType.class;        }                @Override        public List<OneStepOfMultiSteps.BasicDesc> getStepDescriptionList() {            return List.of(new MetadataOfValueType.Desc(), new ConstraintsOfValueType.Desc());        }   ```   以上`getStepDescriptionList()` 返回的是`多步配置插件`中两个子步骤对应的插件的descriptor实例，返回的实例的前后定义了步骤的前后顺序，如：MetadataOfValueType第一步，ConstraintsOfValueType为第二步   子步骤插件的规范请看下`5.`中介绍5. 子步骤插件规范：   如`DefaultOntologyValueType`对应的两个子步骤插件：   1. /Users/mozhenghua/j2ee_solution/project/plugins/tis-ontology-plugin/src/main/java/com/qlangtech/tis/plugin/ontology/impl/valuetype/MetadataOfValueType.java 先通过 MetadataOfValueType.type 属性置顶valueType属于什么类型   2. /Users/mozhenghua/j2ee_solution/project/plugins/tis-ontology-plugin/src/main/java/com/qlangtech/tis/plugin/ontology/impl/valuetype/ConstraintsOfValueType.java 通过 MetadataOfValueType.type 中指定valueType的类型，来进一步设置ConstraintsOfValueType.constraint的`类型约束规则`   子步骤插件的规范相对简单：   1. 插件需要继承 tis-plugin/src/main/java/com/qlangtech/tis/extension/OneStepOfMultiSteps.java 类，可以覆写processPreSaved() 方式，来实现用户提交该步骤时候服务端执行相应的业务逻辑。   2. 内部被@TISExtension标识的Descriptor`必须继承`OneStepOfMultiSteps.BasicDesc类，实现nextPluginDesc() 方法，返回实例告诉TIS该子步骤的后一步执行子插件，如MetadataOfValueType.java:L143 除去以上两点规范外，子步骤插件的规范与TIS普通插件的规范一致，可以使用`.claude/skills/create-plugin/SKILL.md`Skill来创建6. 插件类中如覆写父类`getDescriptor()` 方法   如有覆写`getDescriptor()`方法的情况，则需要添加` @JSONField(serialize = false)` 标注，如:
